# Notion MCP 0.3.0 — Design Spec

- **Date:** 2026-05-26
- **Status:** Approved (design) — pending implementation plan
- **Origin:** brainstorming session (started from a question about migrating auth to a "v3 token")

## Context

The triggering question — "should we move from `token_v2` to a v3 token?" — turned out to be a
non-issue. There is no `token_v3`: `/api/v3` is the **endpoint** version and `token_v2` is the
still-current auth **cookie**; the two version numbers are unrelated. The current auth in
`src/notion-client.ts` is already the correct, current internal-API scheme.

The real outcome is a batch of quality/correctness improvements shipped together as **0.3.0**.
Note: the "Known gaps — next patch" items in `CLAUDE.md` (local image upload, archived-page
preflight) **already shipped in 0.2.0** — that doc section is stale. This release covers what
actually remains.

## Scope (four workstreams)

1. Friendly auth-expiry errors
2. Dedicated append tool
3. Markdown: to-do checkboxes + strikethrough
4. Cleanup + version sync + release

### Non-goals (explicitly deferred)

- **Forward nested-list support.** Importing indented markdown lists as nested Notion blocks is
  deferred to a later focused change. It needs an indent-aware stack parser *and* reworking the
  core `buildCreateOps` transaction builder to recurse (it handles only one child level today, for
  table rows). Bundling it would add risk to an otherwise low-risk release. The **reverse**
  converter already renders nesting from the `content` tree, so deferral causes no regression —
  deeply nested markdown keeps importing flat, exactly as it does today.
- **Migrating to Notion's official bearer-token API.** Would break the project's "no admin/OAuth,
  just a browser cookie" premise and narrow the feature set (export fidelity, inline-anchored
  comments). Out of scope.

## Workstream 1 — Friendly auth-expiry errors

**File:** `src/notion-client.ts` (`notionPost`)

An expired/invalid `token_v2` surfaces two ways today, both as opaque errors. Handle both:

- non-OK response with `res.status === 401`
- HTTP 200 whose JSON envelope has `name === 'UnauthorizedError'`

Both throw one shared, actionable message (single `AUTH_HELP` constant to avoid duplication):

> Notion authentication failed — your `token_v2` session cookie is expired or invalid. Refresh it:
> open notion.so → DevTools (F12) → Application → Cookies → copy the `token_v2` value into
> `NOTION_TOKEN`. (Notion rotates these session cookies periodically.)

Append the raw status + truncated body so debugging info isn't lost.

**Test:** unit test with mocked `globalThis.fetch` returning (a) HTTP 401 and (b) HTTP 200 with
`{ name: 'UnauthorizedError' }`; assert the thrown message contains `token_v2` and `Cookies`.

## Workstream 2 — Dedicated append tool

**Files:** `src/tools/import.ts`, `src/server.ts`

Decision: a **separate tool** (not a `mode` param on import), for clearest intent and zero risk to
existing import semantics.

Refactor `import.ts` to extract shared internals — **no behavior change to existing import**:

- `loadAlivePageBlock(config, id)` → `syncRecordValues` fetch + not-found guard + `alive === false`
  guard; returns the page block (exposing its `content` array).
- `uploadLocalImages(config, blocks)` → the existing image-upload loop (`getUploadFileUrl` → PUT →
  patch `properties`/`format`).
- `buildCreateOps(parentId, blocks, spaceId)` → the existing createOps construction (`set` +
  `listAfter` + timestamps, including one level of children for table rows).

Recompose:

- `importMarkdownToPage` = `loadAlivePageBlock` → delete existing children → convert → validate
  relative-image → `uploadLocalImages` → `buildCreateOps` → `submitTransaction`. (unchanged)
- **New** `appendMarkdownToPage(config, pageId, markdown, baseDir?)` = `loadAlivePageBlock` →
  convert → validate → `uploadLocalImages` → if existing children, set
  `newBlocks[0].after = lastExistingChildId` → `buildCreateOps` → `submitTransaction`. Returns
  `Appended N blocks after M existing blocks.`
- **New** `appendMarkdownFromFile(config, pageId, filePath)` = read file + dirname →
  `appendMarkdownToPage`.

**server.ts:** register two tools mirroring the import pair, with switch cases:

- `notion_append_to_page` (`page_id`, `markdown`)
- `notion_append_to_page_from_file` (`page_id`, `file_path`)

Sharpen `notion_import_page` / `_from_file` descriptions to state plainly that they **replace** all
existing content, so an agent picks append when it means append.

**Risk:** confirm Notion's `listAfter` positions correctly after the last existing child;
positioning via explicit `after: lastExistingChildId` is the safe form — verify during
implementation.

**Test:** unit test that `appendMarkdownToPage`'s generated ops contain no `alive: false` delete
ops and that the first new block's `after` equals the last existing child id (build ops against a
stubbed page block; mock `notionPost`).

## Workstream 3 — Markdown: to-do + strikethrough

Asymmetry found: the **reverse** converter (`from-notion.ts`) already renders `to_do` checkboxes
and nested-list indentation. All gaps are in the **forward** converter. Strikethrough is missing in
both directions.

**Forward** (`src/markdown/to-notion.ts`):

- Before the bulleted-list rule, match `^(\s*)[-*] \[([ xX])\] (.+)$` → `to_do` block with
  `properties: { title: richText(text), checked: [[isX ? 'Yes' : 'No']] }`.
- In `richText()`, add a strikethrough rule `^~~(.+?)~~` → `[text, [['s']]]`; add `~` to the
  plain-text stop set so it isn't swallowed.

**Reverse** (`src/markdown/from-notion.ts`):

- In `richTextToMarkdown`, detect the `s` decoration and wrap the chosen output in `~~…~~` (compose
  with the existing exclusive bold/italic/code/link handling, kept minimal). `to_do` reverse
  rendering already exists.

**Test:** round-trip — `- [x] done` / `- [ ] todo` → forward (assert `to_do` + `checked`) and a
`to_do` block → reverse (assert `- [x]` / `- [ ]`); `~~gone~~` → forward (assert `s` decoration) →
reverse (assert `~~gone~~`).

## Workstream 4 — Cleanup + version sync + release

- Remove `tsx` from `package.json` dependencies (confirmed unused — only self-reference in repo).
- Sync version to `0.3.0`: `package.json`, `server.json` (currently stale at `0.1.8`),
  `src/server.ts` `initialize.serverInfo.version` (currently `0.2.0`). **Recommended:** have
  `server.ts` read `version` from `package.json` to stop future drift.
- `CLAUDE.md`: delete the stale "Known gaps — next patch" section; add the append tools to the
  Tools list; add `to_do` + strikethrough to the block-mapping table; note append-vs-replace.
- `README.md`: add the two append tools + to-do/strikethrough to the feature/tool list.

## Testing & sequencing

- **Gate:** `bun test` green + `bun tsc --noEmit` clean.
- First confirm existing `tests/` don't require live credentials (commit `b41f20e` added real-API
  integration tests). Keep all **new** tests as pure unit tests — mock `fetch`, or call the
  converters / op-builders directly — so they run offline.
- Implement as **four isolated commits in order**: (1) auth message, (2) markdown, (3) append
  (after the `import.ts` refactor), (4) cleanup + version bump.
- Publish (manual, by maintainer): `npm publish --access public --otp=<code>`.

## Open risks

- `listAfter` end-positioning for append — mitigated by explicit `after: lastExistingChildId`.
- Strikethrough composition with other decorations in the reverse converter — kept minimal.
- Existing integration tests may need credentials; new tests must not.
